1. Visão Geral e Tecnologias Necessárias

Para o GoDesc 360 operar com 100% de estabilidade, sem quedas do WhatsApp e sem bloqueios no envio de e-mails, o sistema é estruturado em três pilares interligados:

Componente Tecnologia Responsabilidade Porta / Protocolo
Frontend Web React 19, TypeScript, Tailwind CSS v4, Lucide, Motion, Vite Interface visual de alta performance para clientes e técnicos (Kanban, Chat, Tickets, Financeiro). 80 / 443 (Nginx)
Microserviço de Conexão Node.js 20 LTS, Express, @whiskeysockets/baileys, Nodemailer, CORS Sessão persistente de WhatsApp Multi-Device (QR Code, envio/recebimento de fotos/áudios, chatbot de filas) e envio de alertas SMTP. 10000 (PM2 Daemon)
Banco de Dados & Realtime PostgreSQL / Supabase Realtime Armazenamento relacional com websockets para que novos chamados e mensagens apareçam sem recarregar a página. 5432 / HTTPS Cloud
Por que hospedar em VPS é fundamental? Plataformas gratuitas "serverless" (como Vercel, Netlify ou Render free) congelam a aplicação após poucos minutos de inatividade, matando o socket do WhatsApp e exigindo leitura recorrente de QR Code. Além disso, bloqueiam as portas SMTP 587/465 para evitar spam. Em uma VPS com IP fixo e PM2, o WhatsApp permanece conectado de forma contínua 24/7 e os e-mails chegam de forma imediata aos clientes.

2. Escolha da VPS e Liberação de Portas no Firewall

Você pode contratar a VPS em qualquer provedor de qualidade: Hostinger, Contabo, Hetzner, DigitalOcean, Linode/Akamai, AWS Lightsail ou Oracle Cloud.

Configuração Recomendada da VPS:

  • Sistema Operacional: Ubuntu 22.04 LTS ou Ubuntu 24.04 LTS (64-bit limpo).
  • CPU: 2 núcleos (vCPU).
  • Memória RAM: 2 GB no mínimo (4 GB recomendado para folga operacional).
  • Disco: 25 GB SSD/NVMe.

Portas Necessárias no Firewall (UFW):

Porta Protocolo Serviço Regra UFW
22 TCP Acesso Administrativo SSH sudo ufw allow 22/tcp
80 TCP HTTP Web e validação SSL Let's Encrypt sudo ufw allow 80/tcp
443 TCP HTTPS Seguro (Tráfego de Produção) sudo ufw allow 443/tcp
10000 TCP Microservidor Baileys WhatsApp & API sudo ufw allow 10000/tcp
587 / 465 TCP (Saída) Conexão externa aos provedores de e-mail SMTP (Titan, Google, Hostinger, Outlook) Liberado por padrão nas saídas da VPS

3. Passo a Passo: Preparação do Ambiente na VPS

Conecte-se à sua VPS via terminal SSH (usando PuTTY no Windows ou terminal Linux/Mac):

ssh root@SEU_IP_DA_VPS
  • Atualizar os Repositórios e Pacotes do Linux
    sudo apt update && sudo apt upgrade -y
sudo apt install -y curl wget git build-essential ufw software-properties-common
  • Ativar o Firewall (UFW) de Forma Segura
    sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow 10000/tcp
sudo ufw enable

    Digite y e dê Enter para confirmar a ativação.

  • Instalar o Node.js 20 LTS e PM2
    # Baixar e instalar NodeSource Node.js 20 LTS
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs

# Instalar o PM2 globalmente para gerenciar os processos em segundo plano
sudo npm install -g pm2

    Valide as versões instaladas:

    node -v   # Ex: v20.x.x
npm -v    # Ex: v10.x.x
pm2 -v    # Ex: 5.x.x
  • Instalar o Nginx e o Certbot (SSL Grátis)
    sudo apt install -y nginx certbot python3-certbot-nginx
sudo systemctl enable nginx
sudo systemctl start nginx

6. Configuração do Backend (WhatsApp Baileys & SMTP)

O backend Node.js é responsável por manter a conexão ativa com os servidores do WhatsApp, receber mensagens, fotos, documentos e disparar e-mails corporativos.

  • Instalar Dependências do Microservidor
    cd /var/www/godesc-service-desk/server
npm install
  • Garantir a Pasta de Persistência do WhatsApp (baileys_auth_info)

    A pasta server/baileys_auth_info armazena as chaves de sessão criptografadas do WhatsApp:

    mkdir -p /var/www/godesc-service-desk/server/baileys_auth_info
chmod -R 775 /var/www/godesc-service-desk/server/baileys_auth_info
    Como funciona a persistência: Ao escanear o QR Code pelo sistema, as credenciais de sessão ficam salvas nesta pasta. Mesmo que o servidor seja reiniciado ou o processo do PM2 recarregue, a conexão do WhatsApp é restaurada automaticamente em segundos sem necessidade de ler o QR Code novamente.
  • Iniciar o Microservidor com o PM2 (Auto-Start no Boot)

    Inicie o backend como serviço em segundo plano gerenciado pelo PM2:

    cd /var/www/godesc-service-desk/server
pm2 start index.js --name "godesc-api"
pm2 save
pm2 startup

    O comando pm2 startup exibirá uma linha de comando no terminal (iniciando com sudo env PATH=...). Copie essa linha e execute-a para registrar a inicialização automática no boot do sistema operacional.

  • Verificar o Status do Microservidor
    pm2 status
pm2 logs godesc-api --lines 30

    Você deverá ver a mensagem indicando que o servidor está rodando na porta 10000.

8. Configuração do Nginx (Virtual Host + Proxy Reverso)

O Nginx atuará como servidor web de alta performance para o frontend e fará o proxy reverso da rota /api/ diretamente para o microservidor Node.js na porta 10000, com suporte a WebSockets e limite de upload aumentado para fotos e prints.

  • Criar o Arquivo de Configuração do Nginx
    sudo nano /etc/nginx/sites-available/godesc
  • Colar o Bloco de Configuração Oficial

    Substitua seudominio.com.br pelo seu domínio ou subdomínio real (ex: desk.suaempresa.com.br):

    server {
    listen 80;
    server_name seudominio.com.br www.seudominio.com.br;

    # Limite de upload aumentado para imagens, prints e documentos anexos
    client_max_body_size 50M;

    # Diretório dos arquivos compilados do Frontend
    root /var/www/godesc-service-desk/dist;
    index index.html;

    # Suporte a SPA (Single Page Application - React Router / Navegação interna)
    location / {
        try_files $uri $uri/ /index.html;
    }

    # Proxy Reverso para o Microservidor de WhatsApp & SMTP (Porta 10000)
    location /api/ {
        proxy_pass http://127.0.0.1:10000/;
        proxy_http_version 1.1;

        # Suporte completo a WebSockets e Long-Polling
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        # Cabeçalhos de encaminhamento de IP real do cliente
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # Timeouts estendidos para downloads de mídias do WhatsApp
        proxy_connect_timeout 90s;
        proxy_send_timeout 90s;
        proxy_read_timeout 90s;
    }

    # Cache estático inteligente para CSS, JS, Fontes e Imagens
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff2|woff|ttf)$ {
        expires 30d;
        add_header Cache-Control "public, no-transform";
    }
}

    Salve com Ctrl + O e saia com Ctrl + X.

  • Ativar o Site e Testar a Sintaxe do Nginx
    sudo ln -s /etc/nginx/sites-available/godesc /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t

    Se o retorno for syntax is ok / test is successful, recarregue o Nginx:

    sudo systemctl reload nginx

9. Domínio, DNS e Certificado SSL Gratuito (HTTPS)

1. Apontamento no seu Gerenciador de DNS (Registro.br, Cloudflare, Hostinger):

  • Registro A: Nome @ (ou subdomínio desk) → Apontando para o IP_DA_SUA_VPS.
  • Registro CNAME: Nome www → Apontando para seudominio.com.br.
  • Nota se usar Cloudflare: Deixe a nuvem inicialmente em Cinza (DNS Only) para que o Certbot consiga validar o certificado sem bloqueios. Depois de emitir, você pode reativar o proxy se desejar.

2. Emissão do Certificado SSL com Certbot:

sudo certbot --nginx -d seudominio.com.br -d www.seudominio.com.br

Siga as instruções na tela: informe seu e-mail de contato, aceite os termos (Y) e selecione a opção de redirecionar automaticamente todo o tráfego HTTP para HTTPS (Redirect).

10. Script de Atualização Rápida em 1 Clique (Deploy Contínuo)

Toda vez que você fizer alterações no código e enviar para o GitHub (git push origin main), utilize o script automatizado abaixo na sua VPS para atualizar tudo em segundos: 

nano /var/www/godesc-service-desk/atualizar.sh

Cole o conteúdo:

#!/bin/bash
echo "=== INICIANDO ATUALIZAÇÃO DO GODESC 360 ==="
cd /var/www/godesc-service-desk

# 1. Baixar novidades do GitHub
git pull origin main

# 2. Atualizar dependências e reiniciar backend
cd /var/www/godesc-service-desk/server
npm install
pm2 restart godesc-api

# 3. Atualizar dependências e recompilar frontend
cd /var/www/godesc-service-desk
npm install
npm run build

# 4. Recarregar Nginx
sudo systemctl reload nginx

echo "=== ATUALIZAÇÃO CONCLUÍDA COM SUCESSO! ==="
pm2 status

Dê permissão de execução ao script:

chmod +x /var/www/godesc-service-desk/atualizar.sh

Para atualizar o sistema a qualquer momento, basta rodar:

/var/www/godesc-service-desk/atualizar.sh

Soluções para Dúvidas Comuns:

  • Como resetar a sessão do WhatsApp se o celular for trocado?
    Basta apagar a pasta de sessão e reiniciar o PM2: 
    rm -rf /var/www/godesc-service-desk/server/baileys_auth_info
pm2 restart godesc-api
    Em seguida, acerte o novo pareamento lendo o novo QR Code exibido na tela.
  • Erro 404 ao atualizar páginas internas (F5 no navegador):
    Certifique-se de que a linha try_files $uri $uri/ /index.html; está presente no bloco location / do seu arquivo do Nginx.
  • Como ver os logs ao vivo do WhatsApp e E-mails:
    pm2 logs godesc-api --lines 50
